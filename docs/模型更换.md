# 模型更换指南

本文档说明如何为 DeerFlow 更换、新增或运行时切换 LLM 模型。

## 配置文件与加载机制

所有模型通过配置文件驱动，**不修改任何代码**。

| 文件 | 位置 | 作用 |
| --- | --- | --- |
| `config.yaml` | 仓库根目录（`mini-deer-flow/config.yaml`） | 定义 `models:` 列表 |
| `.env` | 仓库根目录（`mini-deerflow/.env`） | 存放 API 密钥 |

加载流程（见 `backend/packages/harness/deerflow/config/`）：

1. `app_config.py` 读取 `config.yaml`，用 `AppConfig(**yaml_config)` 做 pydantic 校验；
2. 配置文件里的 `$VAR` / `${VAR}` 语法会被展开成对应的环境变量（`_expand_env_vars`）；
3. `.env` 文件由 `load_dotenv` 自动加载，所以 `api_key: $DEEPSEEK_API_KEY` 会被替换成 `.env` 里的真实密钥。

### 关键原理：字段透传

`ModelConfig`（`model_config.py`）声明了 `extra="allow"`，意味着除少数元数据字段外，**所有字段都会原样透传**给 `use` 指定的模型类。所以 `model`、`api_key`、`temperature`、`max_tokens`、`base_url` 等都可以直接写进配置，工厂（`models/factory.py`）只剔除下面这些纯元数据字段：

```
use, name, display_name, description,
supports_thinking, supports_vision, supports_reasoning_effort,
when_thinking_enabled, when_thinking_disabled, thinking
```

## 默认模型规则

> **`config.yaml` 中 `models:` 列表的第一个（`models[0]`）就是默认模型。**

当调用 `create_chat_model()` 不传 `name`，或 `make_lead_agent` 的运行时配置里没有 `model_name` 时，系统自动取列表第一项。**想换默认模型，把对应那段挪到列表最前面即可。**

---

## 三种换法（从简单到灵活）

### 方案 A：就地把 model id 换掉（最简单，推荐）

只想换一个更快的/更新的同提供方模型，直接改 `model:` 这一行。**保持 `name` 不变**，这样代码里按 `name="deepseek"` 的引用不会断；只换传给 DeepSeek 的真实标识符：

```yaml
  - name: deepseek                       # ← 不动：项目内引用名
    display_name: DeepSeek V4 Pro        # ← 显示名，可随意改
    use: langchain_deepseek:ChatDeepSeek # ← 不动：LangChain 类路径
    model: deepseek-v4-pro               # ← 改这里：换成新模型的真实 id
    api_key: $DEEPSEEK_API_KEY           # ← 不动：密钥从 .env 读
    temperature: 0.7
    max_tokens: 8192
    timeout: 600.0
    max_retries: 2
    supports_thinking: false
    supports_vision: false
```

### 方案 B：新增一个模型（保留旧的）

在 `models:` 列表里追加一段即可。新增后有两种使用方式：

```yaml
  # --- 新增 ---
  - name: deepseek-r1
    display_name: DeepSeek R1 (Reasoning)
    use: langchain_deepseek:ChatDeepSeek
    model: deepseek-reasoner
    api_key: $DEEPSEEK_API_KEY
    temperature: 0.7
    max_tokens: 8192
    supports_thinking: true
    supports_vision: false
```

**B1 — 设为默认**：把新模型这段移到 `models:` 列表的第一项（`models[0]`），所有不带 `model_name` 的调用都会用它。

**B2 — 运行时按需切换**：在调用时通过 `configurable.model_name` 指定，不动列表顺序。例如测试 / 调用 Agent 时：

```python
config = {
    "configurable": {
        "thread_id": "t1",
        "model_name": "deepseek-r1",   # ← 指向配置里的 name
    }
}
agent = make_lead_agent(config)
```

`make_lead_agent` 会读 `configurable.model_name`，传给 `create_chat_model(name=...)` 按名称查找。在 LangGraph Studio 里，这个值通过左侧面板的 `configurable` 传入。`model_name` 留空时回落到默认（`models[0]`）。

### 方案 C：换底层提供方（OpenAI 兼容接口）

如果模型只能通过聚合平台（OpenRouter、DeepInfra）或自托管（vLLM）调用，`use` 也要换——不再是 DeepSeek 官方 SDK，而是 OpenAI 兼容类，并需要 `base_url`：

```yaml
  - name: deepseek-v4-or
    display_name: DeepSeek V4 Pro (OpenRouter)
    use: langchain_openai:ChatOpenAI         # ← 换成 OpenAI 兼容类
    model: deepseek/deepseek-v4-pro          # ← 提供方要求的 id 格式
    api_key: $OPENROUTER_API_KEY             # ← 新密钥变量，记得加到 .env
    base_url: https://openrouter.ai/api/v1   # ← 加 base_url
    temperature: 0.7
    max_tokens: 8192
    supports_thinking: false
    supports_vision: false
```

> 项目里已有的 Qwen-VL（走阿里云 DashScope）就是这种 `use: langchain_openai:ChatOpenAI` + `base_url` 的模式，可直接参考。本地 Ollama 则用 `use: langchain_ollama:ChatOllama` + `base_url: http://localhost:11434`。

## 思考模式（Reasoning）

部分模型（如 DeepSeek-R1）支持深度推理。开启方式：

1. 配置里设 `supports_thinking: true`；
2. 调用时传 `thinking_enabled`。在运行时配置里：

```python
config = {
    "configurable": {
        "thread_id": "t1",
        "model_name": "deepseek-r1",
        "thinking_enabled": True,     # ← 开启思考
    }
}
```

`make_lead_agent` 会读 `configurable.thinking_enabled`。开启后，工厂会把该模型的 `when_thinking_enabled`（或别名 `thinking`）里定义的参数合并进构造参数（会深度合并 `extra_body`）。`supports_thinking: false` 的模型即使传了 `thinking_enabled=True` 也不会生效。

## 字段速查

| 字段 | 必填 | 透传给模型 | 说明 |
| --- | :---: | :---: | --- |
| `name` | ✅ | ❌ | 项目内引用名，代码 / `model_name` 用它 |
| `use` | ✅ | ❌ | 模型类路径，如 `langchain_deepseek:ChatDeepSeek` |
| `model` | ✅ | ✅ | 提供方真实模型 id，如 `deepseek-v4-pro` |
| `api_key` | — | ✅ | 通常用 `$ENV_VAR` 从 `.env` 读 |
| `base_url` | — | ✅ | OpenAI 兼容接口 / Ollama 时需要 |
| `temperature` / `max_tokens` / `timeout` / `max_retries` | — | ✅ | 通用生成参数 |
| `display_name` / `description` | — | ❌ | UI 显示用 |
| `supports_thinking` / `supports_vision` / `supports_reasoning_effort` | — | ❌ | 能力声明，工厂/中间件据此启用功能 |
| `when_thinking_enabled` / `thinking` | — | ❌（工厂单独处理） | 开启思考时追加的参数 |

---

## 验证步骤

改完后在 `backend/` 下确认配置能被正确加载和调用：

```bash
cd backend

# 1. 确认 yaml 语法 & pydantic 校验通过，并打印已配置的模型
uv run python -c "from deerflow.config import get_app_config; c=get_app_config(); print([(m.name, m.model) for m in c.models])"

# 2. 确认 .env 里有对应的密钥变量（若方案 C 引入了 $OPENROUTER_API_KEY 等新变量）
grep -i "api_key" ../.env

# 3. 实际创建模型并发一句话，验证密钥有效、模型 id 真实存在
uv run python -c "from deerflow.models import create_chat_model; m=create_chat_model('deepseek'); print(m.invoke('用一句话介绍你自己').content[:80])"
```

第 1 步打印出 `[('deepseek', 'deepseek-v4-pro'), ...]` 即配置生效；第 3 步能返回模型回复，就说明整条链路（配置加载 → 密钥展开 → 模型实例化 → API 调用）都通了。

> 提示：`config.yaml` 支持热重载——`get_app_config()` 会比对文件修改时间，改动后下次调用自动生效，无需重启（仅针对程序内调用；`langgraph dev` 的文件监听会单独处理重启）。
